# Brewfriends — план обучения - 

Учебный трек на живом проекте: Next.js, Vercel, Neon/Drizzle, Cursor-агенты и проверка PR.

Формат: цель → что уже есть в brewfriends → практика → критерий «готово».  
Двигаемся **по одной фазе**: сначала теория коротко, потом руками в этом репо.

---

## Главные цели

1. Понять, как устроен Next.js App Router (страницы, layouts, Server/Client Components, API routes).
2. Понять деплой на Vercel: git → build → env vars → URL.
3. Понять связку «схема в коде → Neon Postgres → приложение».
4. Понять, как Cursor-агенты помогают писать и ревьюить код.
5. Настроить (или хотя бы понять) агентов на проверку pull request.
6. Знать роли агентов: когда какого звать.

### Фаза 4 — Cursor и агенты в разработке

**Цель:** использовать агентов осознанно, а не «магическую кнопку».

Темы:
1. Режимы: Agent (пишет код) vs Plan (план без правок) vs Ask
2. Контекст: `@files`, правила (`AGENTS.md`, rules), skills
3. Что агент видит: репо, терминал, браузер, MCP
4. Хороший промпт: цель, ограничения, «где смотреть», критерий готово
5. Когда **не** отдавать всё агенту (секреты, prod-данные, force push)

Практика:
- [ ] Один фикс сделать сам, один — через агента, сравнить diff
- [ ] Попросить Plan mode на фичу «карта кафе» без кода
- [ ] Написать короткое правило в `.cursor/rules` (например: «repos только в server/repositories»)

**Критерий:** формулируешь задачу так, что агент редко «разъезжается» по лишним файлам.

### Фаза 5 — Агенты на проверку Pull Request

**Цель:** понять автоматический review до merge.

Темы:
1. PR = ветка + diff + описание + checks
2. Кто может ревьюить:
   - **ты / коллега** — смысловой review
   - **Bugbot / bot review** — баги, регрессии, риски в diff
   - **Security review** — секреты, auth, injection
   - **CI** — lint, typecheck, build (не «мнение», а провал/успех)
3. Cursor Cloud Agents / автоматизации на события PR
4. Когда бот полезен, когда шумит

Практика:
- [ ] Создать ветку + маленький PR (например health endpoint)
- [ ] Запустить review агентом по diff ветки
- [ ] Пройти комментарии: что принять / что отклонить
- [ ] (позже) Подключить авто-проверку на каждый PR

**Критерий:** есть хотя бы один PR, по которому прошёл agent review и ты понял вердикт.

### Фаза 6 — Роли агентов (шпаргалка)

| Роль | Зачем | Когда звать |
|------|--------|-------------|
| **Coding agent** | Пишет/правит код | Фича, багфикс, рефактор |
| **Explore / research** | Быстро найти «где что» | Незнакомый участок репо |
| **Plan** | Разбить задачу, без кода | Большая фича, архитектура |
| **Bugbot / code review** | Найти баги в diff | Перед merge PR |
| **Security review** | Риски auth/data/secrets | Auth, API, env, платежи |
| **CI investigator** | Почему упал check | Красный GitHub Action |
| **Docs / explain** | Объяснить поток | Обучение (как сейчас) |

Правило: **один агент — одна роль на один запрос.** Не смешивать «напиши фичу и заодно задеплой и заревьюй security».
